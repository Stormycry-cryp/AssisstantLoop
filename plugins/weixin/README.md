# 个人微信与轻量对话 Agent

参考 [AstrBot 个人微信文档](https://docs.astrbot.app/platform/weixin_oc.html)及其 `weixin_oc` 适配器的接口行为，独立实现 Node 24 的 iLink 客户端。没有复制或导入 AstrBot 的 Python 实现，不安装 AstrBot，不改 Autoloop 内核或 Agent 插件。

微信连接借鉴 AstrBot 的账号、稳定消息编号和回复上下文管理。对话层借鉴 [DSH Superagent 原型](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/004-prompts.md)的主会话与执行会话分工：前台理解意图、承接上下文、给建议与追问；已有 Codex / Pi 执行具体工作。没有安装整套 DSH。任务队列、并发、提问、续接和完成通知仍交给 Autoloop。

## 使用

- "帮我整理这段笔记……"：开启工作；"谢谢"、闲聊和询问进展只回复，不派新任务。
- "绿色吧，不过布局别改"：回答刚才的问题，同时把原话和限制带回原执行会话。
- "你觉得呢？"：先给建议；随后说"就按你建议的办"才记录决定。
- "刚才那个首页再简洁一点"：继续原事项；明确的新工作独立开单，不按主题相似强行续接。
- "先停一下刚才那个首页"：请求停止能唯一定位的当前轮次；不等于暂停定时规则。
- 同时有几件事、指代不清时，只问一句具体问题，不要求记住编号或固定回复格式。
- 默认执行者为 Codex；明确说"这件事用 Pi / Opus 做"可选择已配置的 Pi，之后沿用。前台不会擅自换提供商、权限或目录。

前台是独立的 Pi 模型实例，随微信插件常驻：只聊天、提交本人原话、转达中台已有汇报，不调查代码、不扩写执行计划。使用固定版本的官方 `pi-ai` Models 和 OpenAI Completions adapter，不启动编码助手、工具执行器或额外子进程，不连接 Codex 或共享 Opus App 会话。借鉴 DSH 主 Session 的角色分工与事件回报，没有安装其整套引擎。

固定使用方舟 Agent Plan 的 `deepseek-v4.1-flash` 和 Pi 原生 `low` 思考，专属地址为 `https://ark.cn-beijing.volces.com/api/plan/v3`。请求发出前核验实际模型、`thinking.type: enabled` 和 `reasoning_effort: low`，不自动换模型或通道。上下文由本地最近 24 条已显示对话和当前事项提供，不是无限历史记忆。每条文字只需一次模型生成：宿主将会话快照作为 Pi 原生 `toolResult` 递交，不让模型先读一次工具。固定指令与本人文字分开；提供的工具列表为空，没有实际工具调用或工具循环。

空闲不调用模型、不轮询推理。一个 Pi 客户端复用于后续消息，每次只携带当前受限上下文，不累积完整模型轨迹或思考内容。近期已显示对话随原有私有状态持久化，重启后继续；模型和凭据与后台 Codex / Pi 执行者分别绑定。

公开版的基础人设在 [persona.md](persona.md)。首次向导先选简洁、专业或温和风格，再设置名字、称呼和可选具体偏好；个性设置保存在 `${AGENT_AUTOLOOP_HOME:-~/.assisstantloop}/persona.md`，通过 `frontdeskPersonaFile` 加载，更新程序不会覆盖。宿主统一将本人看到的文字排成每行最多 30 字，移除句号、标题、列表和加粗，最多一个 emoji；不会改写提交给执行者的原话。最近对话之外，最多保留 32 条本人直接告知的偏好或近况，均作为资料读取，不作为权限或指令。上海时间 23:00 至次日 06:00 可在仍忙时催睡，每晚最多一次，跨重启保留。

每条文字消耗 Agent Plan 套餐额度，真实费用未知，Pi 目录的零成本占位不代表免费。网络和模型服务会影响实际延迟；调用失败时明确说明尚未执行，不伪造秒回。

执行会话的提问与结果先由 助理 理解后自然转述，不直接显示标题、选项列表、建议索引或固定回答格式。需要本人拍板时保留实际决定和代价，不代选、不把建议说成已决定。选项与原卡片引用留在宿主，下一句普通回复仍可对应回原问题。每次汇报只生成一次转述，发送前持久化，重试复用；最多保留 8 条待发稿，不把模型失败降级成原始菜单。中间决定状态及同一回执的重复摘要仍省去。收消息与转述共用一个 Pi 实例，最多两条在途请求串行处理，空闲不调用模型。

目前支持文字、图片及微信已转录成文字的语音。视频和文件内容暂未接通。只接收扫码本人私聊中的原始图片项，不读取群聊、陌生人或引用里的附件；从固定微信 CDN 下载，支持 iLink 的 AES-128-ECB 图片解密，不把微信 token 传到 CDN，不跟随重定向。识别 PNG、JPEG、WebP、GIF，每次最多两张、每张解密后不超过 4 MiB，下载流也限制大小。

图片通过 Pi 原生 image 数据块交给现有 DeepSeek 模型，不另启动视觉 Agent。可见事实与不确定处随最近对话保存；原图内容、Base64、下载参数和解密密钥不写入状态、日志或事件。本人需要执行工作时，宿主把原话、标明是资料的读图摘要，以及宿主生成的原图路径一起交给 AutoLoop；回答现有问题时续接原事项和会话。文字与图片分开发送时，前台可明确选用最近 24 小时内的一组图片摘要，宿主带上其保存路径，不重复上传或假装重新看过原图；不确定的细节需补图。纯分享和看图聊天不派新任务。下载或识别失败时明确说明没读到，不单独执行随图文字。

原图保存一次并在重放时复用，位于 `${AGENT_AUTOLOOP_HOME:-~/.assisstantloop}/work/weixin/attachments/`，目录 0700、文件 0600，文件名由宿主散列产生。它们是本人输入资料，最多 32 张、累计 32 MiB；达到上限停止接纳新图并提示确认清理，不自动删除待办任务可能引用的原图。收尾由本人确认退役，不属于可随意轮换的测试输出。事件仍用原有文字协议，超过 4000 字的交办资料拒绝提交并提示拆短，不截断原话。需要操作的目录和模型由本机规则固定；消息不能提供运行目录、权限、命令或凭据。初始任务工作区固定为上述 weixin 目录，其他安装如改规则目录，应同时检查保存路径对原执行者是否可读；访问其他项目前仍须明确授权。

## 登录与安装

手机微信须包含 ClawBot 插件。执行：

```sh
AGENT_AUTOLOOP_HOME="$HOME/.assisstantloop" node plugins/weixin/login.ts start
AGENT_AUTOLOOP_HOME="$HOME/.assisstantloop" node plugins/weixin/login.ts wait
```

登录内容只写到 `${AGENT_AUTOLOOP_HOME:-~/.assisstantloop}/weixin/`。`qr-content.txt` 是供本机制码的内容，不要发到第三方制码服务；二维码与等待状态为一次性材料，确认或过期后退役。token、账号及扫码人的微信身份写入 `account.json`，权限为 0600。`state.json` 保存回复上下文、游标、去重记录和卡片投递映射，也为 0600；两者为私有持久数据，不进入源码仓库或临时清理目录。

推荐直接运行 `assisstantloop setup`，先设人设再完成扫码和规则配置。手动安装时，可将插件目录放到 `~/.assisstantloop/plugins/weixin`。在可信 `rules.json` 登记 `sources.weixin`、`channels.weixin`（`answerers` 只含扫码人），以及匹配 `task.codex`、`task.pi` 的固定规则。微信任务使用 `tell: "always"` 复用中台的完成摘要通知；无需额外结果轮询器。共享工作区的规则使用同一个 `group` 和 `parallel: 1`，避免两个 Agent 同时修改文件。

`config.json` 的 `channels.weixin` 配置已有通道密钥、`use: "weixin"`、`accountFile` 及专用 `sourceKey`。前台的 `frontdeskModel` 必须为 `deepseek-v4.1-flash`；`frontdeskPiRoot` 指向数据目录的 `pi-runtime`，向导安装 `@earendil-works/pi-ai@1.4.0` 和 `qrcode-terminal@0.12.0`，不安装编码助手；`frontdeskCredentialFile` 指向已有、权限为 0600 的 Agent Plan 私有配置（其中有 `AGENT_API_KEY=...`），仅由宿主读取，或使用宿主已有 `AGENT_API_KEY`。未指定时使用本安装数据目录的 `pi-runtime` 与 `agent-plan.env`；没有有效专属 Key 就停止入口，不改用 Codex、Opus Key 或按量付费地址。

插件仅连接本机回环中台，用已有本人密钥查询状态和停止；模型拿不到这些配置字段。执行规则应说明：问题用自然中文；回答的 `choice` 与 `text` 一起看，不能丢掉本人原话里的限制。配置完成并确认没有正在执行的任务后，重启本中台服务。

主动沟通保留，但同一回执关闭旧问题、新建问题、附带摘要时只转述需要本人知道的业务内容。旧问题的结案和自动摘要不会再各发一遍；普通通知若仅重复已显示的内容，前台返回静默决定，宿主确认回执但不再发微信。真正的新问题、新结果、新风险与状态变化仍会主动汇报。能力或状态追问（如“看不到图？”）不再成为新的执行任务。

## 连续性与权限

- 仅接受扫码人的私聊入站消息，过滤其他发送者、群消息、机器人出站消息和引用中的命令。不会接管好友列表或遍历现有聊天记录。
- 事件编号来自账号与原消息编号的散列。回复丢失重放时复用原事件编号；整批接纳后才提交长轮询游标，避免丢单或重复执行。
- 回答核对本人、当前仍待答的卡片及原投递引用。多个问题同时打开时，禁止把一个裸数字猜成某张问题的答案。
- 前台没有 shell、应用、插件、浏览器、子代理、MCP、hooks 或任意文件读写工具，不加载 Codex 登录、用户配置或全局默认模型；开启本机观察后，只接收宿主筛出的会话状态与有限摘要。固定主提示词与当前消息分开，消息、近期对话及任务快照以 Pi 原生工具输出递交，不拼入指令。配置、模型 Key、微信 token、原消息引用与中台密钥不传给模型。输出使用 JSON 格式并由宿主按严格 schema 和已显示问题、已知事项、固定执行者白名单核验；只接受 `stop` 完成的纯文字决定，错误、中断、截断及工具调用不能产生动作。
- 决定先持久化，再按稳定编号提交动作；消息重放复用已经冻结的决定，避免再次调用模型改变答案。卡片回答前再查当前状态，已结束的问题不能被重复回答。微信接口响应丢失仍可能造成重复文字提醒。
- 通知先保存成功投递记录，再向中台确认；确认丢失重取卡片时不重复发送。网络结果未知时仍可能重复收到同一提醒，不能宣称微信接口提供了未经验证的绝对幂等保证。
- 登录失效时用桌面等现有通道提示本人恢复，不调用模型反复重试。重登必须保持原绑定；换号不能自动复用旧私有状态。
- 主动通知依赖微信发消息接口允许投递及已保存的 `context_token`，不是无条件的无限期推送。上下文不可用时，请在微信再发一条消息刷新；后台仍保留卡片，不把未送达说成已送达。

## 容量与验收

单条任务上限 8000 字节，微信输出上限 12 KiB，微信 HTTP 响应上限 1 MiB，私有 JSON 文件上限 256 KiB；超限保留已有数据并报告。最多保留 2048 个近期消息散列及 256 个卡片映射，优先退役已收尾卡片；活跃映射满时阻止新增投递，不清空未处理项。前台读取最多 20 个问题、20 个近期事项及 24 条对话；本次快照最多 128 KiB，只在内存中交给模型，不生成快照文件。模型单次输出（含思考）最多 2048 tokens，最终决定最多 16 KiB，最多等 60 秒，超时或停止时中止 Pi 请求。宿主只在内存保留最近一次型号、耗时和原生 token 用量，不记录正文、思考或凭据。根项目不新增运行时依赖，向导只在数据目录安装固定 Pi SDK 和本地二维码工具；每次插件启动最多记录 10 条不含凭据、正文和完整快照的诊断。原子替换固定 `.tmp`，下次写入覆盖本任务遗留候选，不创建无上限的新目录。

```sh
node --disable-warning=ExperimentalWarning --test tests/weixin.test.ts tests/weixin-conversation.test.ts
npm run test:quick
npm run typecheck
npm run format:check
```

测试使用临时中台、随机端口和假微信传输，不发真实消息、不调用模型，结束清理。包含自然回答与原始限制在同一执行会话续接、歧义拒绝、重放不重复理解、资料与指令分离、Pi 实例复用与输出失败拒绝、结果只投递一次。真实模型验收须另行显式运行，记录所用模型、供应商返回型号、推理强度、延迟和语义结果；实际微信验收仍需本人扫码并完成一次任务、一次回答、一次结果回传。

登记 `codex-desktop` 执行者及 `task.desktop` 规则后，微信可说“让桌面 Codex 做……”。宿主仅在登记且明确选择桌面时开放路由，查询、回答、停止沿已有事项，见[桌面插件](../codex-desktop/README.md)。

## 本机手工会话与进程读取

本机配置显式设置 `channels.weixin.observeLocalAgents: true` 后，前台也能看到用户直接在 Codex / Pi 中启动的会话；这不需要从微信重新派一次任务。Codex 只读本机 `state_*.sqlite` 与该目录内的会话记录，Pi 通过原生本机接口读取；只采集标题、轮次、状态和最多 400 字的最终摘要，不读取模型凭据，不把思考或工具历史交给前台。原始本机会话记录为版本相关格式，读不到时明确标为未确认，不能把过时活动当作完成。

Pi 的观察连接单独申请 `orchestration:read`，没有提交或停止任务、写入文件、运行终端命令的权限。已安装本机 Pi 宿主后，执行 `node plugins/weixin/pair-pi.ts --run`；凭据仅保存在私有数据目录的 `local-activity/pi-read.json`，0600。公开安装默认关闭观察，是否启用由安装者决定；不得复制作者配置或观察凭据。

每 15 秒核对一次，按需查询复用缓存。最多读取 Codex 最近 40 条与 Pi 最近 40 条，前台最多展示 40 条并优先展示正在运行的会话。首次扫描只建立基线，不补发全部历史；之后观察到本机轮次结束、失败或停止时，使用稳定通知编号经过中台汇报。观察状态最多 128 条，未送达通知最多 16 条、状态文件最多 128 KiB，未知结果不猜成完成；回复丢失复用通知编号。中台自己派发的会话会排除，避免双重汇报。手工会话不变成可操作的任务，续接和停止仍须明确绑定；中台任务计数与观察到的会话数量分别显示，不能因中台队列为空就说整台电脑没有任务。

单独发“？”“结果呢”等短追问时，宿主直接按已知状态回答，不调用模型、不再次派活。终态回执如果没有同轮业务卡片代为汇报，不能被模型按“和旧问题相似”静默丢弃；同轮重复卡片和已送达重放仍去重。

本人明确要求查看活跃进程、进程占用或系统自检时，宿主使用固定 `/bin/ps -axo pid=,pcpu=,rss=,comm=` 只读采样，给执行者附带采样时间和前五项 CPU / 内存记录；不收集完整命令行或环境，不允许本人消息替换命令，不放宽执行器整体权限。单次超时 5 秒、输出上限 256 KiB，采样与原消息一起冻结，重放不重新采样。数据是采样时刻的资料，不是持续监测，也不表示可以删除文件或停止进程。

会话来源分开报告：应用、项目、会话所选模型和来源机器；Pi 是底层框架，不能替代应用名称。Pi 观察范围是本机共享宿主中的 App、网页与 `opus-agent-ui` 会话，独立 Pi CLI 私有会话尚未列入此观察范围。
